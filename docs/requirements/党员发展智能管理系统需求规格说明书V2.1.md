# 2　项目概述

## 2.1　项目定位

本项目不是又一个“党务信息发布平台”，而是面向基层党务助理与支部书记的“党员发展流程智能副驾驶”：以人为单位、以材料为证据、以时间为刻度，把党员发展从“靠人记、靠人催、靠人看”的台账式管理，转变为“流程可锁、材料可核、时限可算、风险可见”的闭环管理。其中“三锁”指流程锁、材料锁、时限锁；“三防”指防漏项、防造假、防泄密，分别由规则核验、一致性与雷同检测、脱敏与审计留痕落地。

系统采用轻量化路线：网页端交付、调用成熟大模型 API 完成语义核验、规则与模板全部配置化，不依赖重型中间件与高并发架构，三名学生在一个学期内可完成可用版本并形成完整申报与结题材料。

# 3　创新点设计

## 3.1　总体创新思路

本项目的创新点不在于“用了大模型”，而在于把党务工作中依赖经验的判断，拆解为可计算、可解释、可追溯的规则与指标，让“三锁三防”从一段管理制度文字，变成系统里真正能拦住错误动作的判定逻辑，以及能排序、能比较的合规分数。

围绕这一思路，本章提出五个创新点：前两个解决“核验准不准”，第三个解决“水平高不高”，第四个解决“时间够不够”，第五个解决“信息敢不敢放”。每个创新点均按“现状做法—本项目做法—技术路径—创新价值”四段说明，并在 3.7 给出取舍建议，供申报时按团队能力选择主打点。

## 3.2　创新点一：规则引擎与大模型双引擎核验

现状做法：多数同类方案把材料原文整段交给大模型，让它直接判断“是否合格”。这种做法有两个无法回避的缺陷：一是大模型存在幻觉，可能漏判硬性要素；二是结论不可解释，支部书记无法判断“AI 说不合格”到底依据什么，最终仍要人工重看一遍，效率提升有限。

本项目做法：把核验拆成三层。第一层是规则引擎，负责确定性判断，包括材料是否上传、文件类型与命名是否匹配阶段、页数与份数是否达标、关键要素字段（姓名、日期、单位、结论语、签章位置）是否存在、时间逻辑是否成立（例如思想汇报日期不得早于确定积极分子的日期）。第二层是大模型，负责语义判断，包括内容是否切题、是否出现空话套话、是否覆盖本阶段要求的思想认识要点。第三层是结论合成：规则命中为硬性缺项，不可申诉；模型判断为语义存疑，人工可采纳或驳回，且每条结论都回链到原文片段与命中的规则编号。

技术路径：规则以 JSON 配置存储，由后台维护，新增一条核验要点不需要改代码；大模型调用强制输出 JSON 结构，解析失败自动重试一次，仍失败则降级为“待人工”，并在报告中标明原因；核验报告保存命中的规则编号、原文定位段落和模型置信度，形成可复查的证据链。

创新价值：这套设计同时解决了“准”和“信”两个问题，是同类学生项目中较少见的工程化处理。由于规则与提示词均可配置，系统在第二年、第三年材料要求变化时不需要重写，具备真实推广价值。

## 3.3　创新点二：材料锁从“查缺项”升级为“查一致、查雷同”

现状做法：材料锁通常只回答一个问题——材料交了没有。但党务工作的真实困扰常常是“材料都在，内容对不上”：家庭成员信息在登记表和政审材料里不一致，函调回函的结论与政审报告结论相反，思想汇报直接抄网络文章或抄同支部同学。

本项目做法：在齐备性之上增加两层校验。第一层是一致性校验（纵向），跨材料、跨表单比对同一事实：家庭成员姓名、关系、工作单位、政治面貌在登记表、政审材料、函调回函之间是否一致；申请书日期、确定积极分子日期、培养满一年、发展对象、预备期一年是否构成合法时间链；政审结论与函调结论是否矛盾。第二层是雷同检测（横向），对同一支部同批次的思想汇报两两比对，输出相似度矩阵与疑似雷同对。

技术路径：一致性校验采用“结构化抽取＋字段比对”，由大模型把非结构化材料抽成键值对，再由规则引擎做比对和冲突标注；雷同检测采用“文本规范化—去除模板句—SimHash 指纹粗筛—向量余弦精排—大模型判定”的漏斗式流程，先低成本筛出可疑对，再用模型判断是“引用规范表述”还是“实质性抄袭”。

创新价值：这两项能力直接对应党务工作中最难量化、最耗人力的部分，也是当前同类案例尚未覆盖的空白。一期先做一致性校验的基础字段比对，雷同检测作为二期扩展，即使只实现“相似度排序＋人工判断”，也足以形成明显的演示效果。

## 3.4　创新点三：把“三锁”量化为合规指数与支部热力图

现状做法：三锁只表现为“能不能点下一步”的开关，管理者知道谁被卡住了，但不知道整体风险有多大、哪个支部最需要介入。

本项目做法：定义合规指数 C＝0.40×M＋0.35×T＋0.25×Q，三个分项均折算为 0—100 分后加权。分项定义如下：

- **M 材料完整度**：M＝100×已通过必填材料数÷应提交必填材料数；无必填材料时记 100。
- **T 时效健康度**：T＝100×(1－Σw÷N)。N 为已触发时限节点数；w 按节点级别取值：逾期 1.0、紧迫 0.6、临期 0.3、提示 0.1、正常 0；结果截断到 0—100。
- **Q 内容质量分**：Q＝100×(1－(1.0×冲突数＋0.7×存疑数＋0.5×语义缺失数＋0.3×低置信数)÷语义要点总数)；结果截断到 0—100。

输出三个层级：人员级指数、支部级均值与分布、风险清单（低于 60 分标红，60—79.99 分标黄，80 分及以上标绿）。权重、扣分系数与分档阈值均做成可配置参数，修改后在下一个计算周期生效。

技术路径：全部为确定性计算，使用已有数据，无需额外模型调用，实现成本低、演示效果直观。指数权重做成可配置参数，便于根据实际反馈调整。

创新价值：它把“三锁”从阻止动作的机制，变成可比较、可排序的治理指标。支部书记打开看板就能知道本周该找谁谈话，学院层面可以看到支部之间的差距，这是党务管理从经验判断走向指标治理的具体体现。

## 3.5　创新点四：时限锁升级为倒推排期与影响模拟

现状做法：时限管理停留在“到期提醒”，属于事后补救。支部书记被提醒时，往往已经没有缓冲时间完成考察或补材料。

本项目做法：把时间维度反过来算。输入“拟转正季度”或上级批复时间，系统按规则库反推每个节点的最晚完成日期，生成支部年度发展日历，回答“这个月必须完成哪几件事”。同时提供影响模拟：如果本月未完成季度考察，转正日期将顺延至某月，是否影响学生在毕业前转正，一目了然。

技术路径：纯规则计算，按节点依赖关系做逆序推演，输出甘特式时间轴。节点分为固定偏移型、事件依赖型和周期型：固定偏移型按起算日加天数/月数计算；事件依赖型在前置事件完成后计算，未触发时显示“待触发”；周期型（如思想汇报）按季度生成独立实例。不需要模型参与，开发成本低，但对使用者最实用。

创新价值：从“催办”变成“排产”，是五个创新点中投入产出比最高的一个，建议一期就实现。

## 3.6　创新点五：敏感字段分级与全链路留痕

现状做法：政审材料、函调回函包含家庭成员的工作单位、社会关系甚至身份证号，现实中常在聊天群里流转，谁看过、转发给谁都没有记录。

本项目做法：按字段设定可见级别，分为完整可见、掩码可见、不可见三档；按角色与支部做双重可见范围控制；对材料查看行为记录“谁、何时、看了谁的哪份材料”；导出文件自动加“姓名＋用途＋时间”水印，并保留导出记录。

技术路径：身份证号、手机号等敏感字段采用 AES-GCM 加密存储，同时保存掩码值用于列表展示；字段级脱敏在展示层完成，完整值通过单独接口按权限解密并记录理由。政审材料文件存放于非公开目录，通过鉴权接口访问。审计日志独立存储，普通角色无法删除。发送至大模型前必须剥离身份证号、手机号、住址和姓名，只发送核验必需的脱敏文本。

创新价值：这一条不追求技术难度，但它决定了系统“敢不敢真用”。评审时这往往是学生项目最容易失分、也最容易补分的地方。

## 3.8　申报书可直接引用的表述

以下三段文字按大创申报书常见栏目撰写，可直接引用，使用时应按实际进展替换括号内的占位内容。

（一）研究内容与特色。本项目面向高校党员发展工作的材料核验与流程管控环节，构建“规则引擎＋大模型”双引擎核验机制：规则层负责材料齐备性、格式规范性与时间逻辑的确定性判断，模型层负责内容切题性与跨材料一致性的语义判断，二者合成的核验结论逐条回链原文片段与规则编号，既提升核验效率，也保证结论可解释、可复核。在此基础上，项目提出合规指数模型，将“流程锁、材料锁、时限锁”量化为可排序的治理指标，实现从流程管控到风险画像的升级。

（二）技术路线特色。系统采用轻量化三层架构：前端网页端承载台账、看板与核验结果展示；服务层以配置驱动的规则引擎完成确定性校验，并封装大模型接口完成语义校验与信息抽取；数据层以结构化方式存储人员、材料、阶段与审计记录。全部核验要点、时限参数与材料清单以配置形式管理，不写死在代码中，使系统具备跨学院、跨年度复用的能力。

（三）应用价值与推广前景。项目成果可直接服务于学院党员发展台账管理、材料预审与节点催办，预期将单份材料核验时间由【待测】压缩至 1 分钟以内，台账汇总由【待测】缩短至 5 分钟以内，并通过预警机制降低逾期风险。系统参数化设计使其可低成本推广至校内其他学院乃至同类基层党组织；同时，项目在一期完成后可继续深化一致性校验与雷同检测，具备延续为本科毕业设计的技术空间。

## 5.3　阶段流转判定规则

点击“推进阶段”时，系统按以下六项规则逐条判定，任一不满足即拒绝流转，并在弹窗中列出全部未满足项，避免逐条试错。

> 规则一（材料锁）：本阶段清单内全部必填材料状态均为“已通过”，且份数、页数满足清单要求。
>
> 规则二（时限锁）：本阶段关键时限未超过允许范围；若已逾期，须由支部书记填写逾期说明后才可继续。
>
> 规则三（流程锁）：不存在未处理完毕的退回项，且上一阶段的归档动作已完成。
>
> 规则四（备案完整性）：需要上级备案或审批的节点，备案日期与批复日期已登记（由超级管理员设置），不允许先推进后补录。
>
> 规则五（操作权限）：当前账号具备该支部的推进权限，且对象属于其管理范围。
>
> 规则六（二次确认）：操作需二次确认并填写推进依据（如支部会议日期），确认记录写入流转日志。

- **固定偏移型**：T-01、T-02、T-04、T-05、T-08、T-10、T-11，按起算日加天数或月数计算。

- **周期型**：T-03 按季度生成独立实例，每个季度一条预警，周期键为 `YYYYQn`，避免重复或遗漏。

·格式写法 “30/15/7/3 天” 表示四级提醒：提前 30 天提示、提前 15 天和 7 天临期、提前 3 天紧迫；超过应完成日即为逾期。

## 7.2　关键字段与主键约定

为提高开发效率与后续可读性，库表字段统一采用下划线命名，主键以“表缩写_id”命名，时间字段统一使用日期时间类型并以服务器时间为准，枚举字段一律使用代码值存储、界面显示中文名称，避免中文枚举入库导致统计错乱。

> 人员主键 person_id，学号唯一索引，避免同一学生重复建档；学号逻辑删除后不复用，确需恢复走管理员审批流程。
>
> 材料主键 material_id，外键关联 person_id 与阶段，材料类型取自清单模板，不允许自由填写。
>
> 核验报告主键 report_id，保留模型版本号、提示词版本号与规则版本号，便于复现历史结论。
>
> 身份证号采用 AES-GCM 加密存储，同时保存掩码列；完整值不进入列表接口、导出默认文件与普通日志。
>
> 系统账号 User 与人员 Person 通过 person_id 关联：R4 必须绑定且只能绑定一个 Person，R1—R3 可为空；服务层据此强制“学生只看本人”。
>
> 所有删除操作采用逻辑删除标记，不物理删除材料与日志。

## 8.2　安全与合规要求

> 身份与访问：密码加盐哈希存储，接口层做角色与支部双重校验，越权访问拒绝并留痕。
>
> 敏感信息：按 4.3 分级脱敏；身份证号、手机号等字段 AES-GCM 加密存储，列表默认掩码，完整值仅 R2 及以上角色填写理由后查看并记录；导出文件加水印。
>
> 传输与存储：全站启用 HTTPS；材料文件存放于非公开目录，通过鉴权接口访问，不提供裸链接。
>
> 数据边界：演示与测试一律使用虚构数据，禁止将真实政审材料上传至公网环境；确需使用真实材料时，须经指导教师同意并做脱敏处理。
>
> 模型合规：发送大模型前剥离身份证号、手机号、住址与姓名，只发送核验必需文本；选用承诺“不用于训练、不留存”的服务条款，并在系统内记录模型名与提示词版本。
>
> 可恢复性：备份范围包括数据库与材料文件目录；数据库建议每日、文件建议每周备份，重要节点前额外备份；每季度至少做一次恢复演练，附恢复说明。

## 8.3　易用性要求

使用者是党务工作者而非软件工程师，界面设计遵循三条：核心任务不超过三次点击完成；任何拦截都说明原因并给出下一步动作；所有术语使用党务工作中的原有说法，不另造新词。

## 8.4　兼容性与部署

系统为网页端应用，支持 Chrome、Edge 最近两个大版本，最小分辨率 1366×768。部署采用单机方案，可运行于一台校内服务器或个人电脑，数据库使用 MySQL 8.0（InnoDB、utf8mb4），大模型能力通过 API 调用，不本地部署模型，以降低硬件门槛。

## 8.5　可维护与可扩展

所有业务规则、材料清单、时限参数、提示词均以配置文件或数据库记录形式管理，调整时不修改业务代码；模块间通过接口解耦，便于二期单独替换核验模块或增加移动端；代码需附接口说明文档，保证毕业后可交接。
