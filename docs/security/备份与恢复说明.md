# 数据备份与恢复说明

> 适用对象：系统管理员、项目负责人、答辩演示保障人员。
> 备份范围必须同时包含 **MySQL 数据库** 与 **材料文件目录**，只备份数据库会导致材料文件丢失。

## 1. 备份策略

| 项 | 建议 |
| --- | --- |
| 数据库 | 每日 02:00 全量 `mysqldump` |
| 材料文件 | 每周全量 `tar.gz`；重要节点前额外备份 |
| 保留周期 | 28 天（可按学校要求调整） |
| 存放位置 | `/data/party-backup` 或学校受控存储 |
| 恢复演练 | 每月至少一次；重要演示前一次 |
| 目标 | RPO ≤1 天；RTO ≤4 小时 |

## 2. 执行备份

```bash
cd /root/develop/Party_Building_System
bash scripts/backup.sh
```

脚本会：

1. 读取项目 `.env` 中的数据库配置；
2. 导出 `party_build` 数据库为 `*.sql.gz`；
3. 打包 `FILE_ROOT` 材料目录为 `*.tar.gz`；
4. 生成 SHA-256 校验文件；
5. 删除超过 28 天的旧备份。

cron 示例：

```cron
0 2 * * * cd /root/develop/Party_Building_System && bash scripts/backup.sh >> /var/log/party-backup.log 2>&1
```

## 3. 备份目录示例

```text
/data/party-backup/
├── db/
│   ├── party_build-20261112-020000.sql.gz
│   └── party_build-20261112-020000.sql.gz.sha256
└── files/
    ├── party-files-20261112-020000.tar.gz
    └── party-files-20261112-020000.tar.gz.sha256
```

## 4. 恢复步骤

> 恢复前先停止应用，避免写入覆盖。

### 4.1 恢复数据库

```bash
gunzip -c /data/party-backup/db/party_build-YYYYMMDD-HHMMSS.sql.gz | mysql -u party -p party_build
```

### 4.2 恢复材料文件

```bash
tar -xzf /data/party-backup/files/party-files-YYYYMMDD-HHMMSS.tar.gz -C /path/to/parent
```

确保恢复后的目录与 `FILE_ROOT` 一致，例如：

```text
FILE_ROOT=/root/develop/Party_Building_System/backend/data/files
```

### 4.3 校验

```bash
sha256sum -c /data/party-backup/db/party_build-YYYYMMDD-HHMMSS.sql.gz.sha256
sha256sum -c /data/party-backup/files/party-files-YYYYMMDD-HHMMSS.tar.gz.sha256
```

启动后端后抽查：

- 登录；
- 人员台账；
- 材料下载；
- 归档包下载；
- 审计日志查询。

## 5. 安全要求

1. 备份文件包含个人信息与政审材料，必须存放在受控目录，禁止公网共享。
2. 备份目录权限建议 `700`，仅应用管理员可读。
3. 如使用云盘/对象存储，必须加密并限制访问。
4. 演示环境只使用虚构数据；真实材料备份按学校数据管理规定执行。
5. 禁止通过系统 Web 接口直接下载整库，避免越权与泄露。

## 6. 与审计日志的关系

- 审计日志本身在数据库中，随数据库备份一起保存；
- 日志只增不改不删，应用不提供删除接口；
- 建议重要节点前额外导出一份审计日志 CSV/Excel 留档；
- 数据库账号不应授予普通业务账号 `DELETE` 权限。

## 7. 当前 POC 说明

当前云服务器演示环境未自动执行 cron，需手动运行：

```bash
cd /root/develop/Party_Building_System
bash scripts/backup.sh
```

正式使用前应配置定时任务、异地备份与恢复演练记录。
